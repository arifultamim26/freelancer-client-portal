# Studio Desk — Freelancer Client Portal

A private project workspace for a freelancer and their clients. Clients can follow milestones, open shared deliverables, read invoice status, and leave feedback. The freelancer manages project records through Django Admin.

> **Portfolio demo:** use fictional names and invoice values. This app tracks invoice status only; it does not collect payments. Deliverables are external links in this first release, so do not paste private or access-token URLs into a public demo.

## Why this project

Studio Desk solves a familiar coordination problem and demonstrates more than basic CRUD: authenticated roles, per-project authorization, relational models, workflow status, feedback, admin management, responsive pages, PostgreSQL deployment, and automated checks.

## First release

- Sign-in for pre-created freelancer and client accounts.
- A dashboard listing only projects the signed-in user belongs to.
- Project pages with milestones, shared links, feedback, and invoice status.
- Client-only feedback, limited to milestones on that project.
- Django Admin for the freelancer to manage projects and related records.
- SQLite locally; PostgreSQL in production.

Not included: public account registration, payment processing, email notifications, or file uploads. Those boundaries keep the first release small and avoid accepting personal documents or payment details.

## Architecture

```text
Browser
  └── Django templates + responsive CSS
       └── Django views (login required; project scoped to current user)
            ├── Django ORM → PostgreSQL in production / SQLite locally
            └── Django Admin → freelancer-managed records
```

Core records: `Profile` (role), `Project` (freelancer + client), `Milestone`, `Deliverable` (URL only), `Invoice` (amount and status only), and `Feedback`. Project lookups start from `Project.visible_to(user)`. Feedback also verifies that the signed-in user is the assigned client and limits milestone choices to that project.

## Run locally

You need Python 3.12 and Git. If `python3 -m venv .venv` reports that `ensurepip` is missing on Pop!_OS or Ubuntu, install the matching venv package with `sudo apt install python3.12-venv`, then retry.

```bash
git clone <your-repository-url>
cd <your-repository-folder>
python3 -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Open <http://127.0.0.1:8000/>. Sign in with the superuser (the demo freelancer/admin), open **Manage**, and create a normal user for each fictional client. In Django Admin, create a `Profile` with the `Client` role, then create a project and assign its client and freelancer users. Add milestones, deliverables, and invoices. Never use real client or billing information in a public demo.

The app defaults to local SQLite and development mode when environment variables are not set. `.env.example` lists optional variables; export them in your shell or use your preferred environment-file tool if you want to override the defaults.

## Check and test

```bash
python manage.py check
python manage.py test
```

The suite checks anonymous redirects, client and freelancer project boundaries, cross-client URLs, client-only feedback, feedback author assignment, rejection of a milestone from another project, and milestone progress as statuses change.

GitHub Actions runs the system check, migration check, and test suite on each push and pull request.

## Deploy on Render

`render.yaml` defines a web service and PostgreSQL database. Its selected plans have costs; review current Render pricing and database retention before applying it.

1. Push this repository to GitHub.
2. In Render, create a **New Blueprint Instance** and select the repository.
3. Review the services and current prices, then apply the Blueprint.
4. Wait for the build and migrations to finish.
5. Open the service Shell and run `python manage.py createsuperuser`.
6. Sign in, create fictional demo users and records, then test client separation in separate browser profiles.

`SECRET_KEY` is generated by Render, `DEBUG` is disabled, PostgreSQL is connected through `DATABASE_URL`, and WhiteNoise serves collected static files. Do not commit secrets. Set `ALLOWED_HOSTS` if you use a custom domain.

## Demo walkthrough

1. Sign in as the freelancer and open a sample project.
2. Review its milestone timeline, deliverable link, and invoice status.
3. Sign out and sign in as the assigned client.
4. Leave feedback on one milestone and confirm it appears on the project page.
5. Sign in as another client and confirm the first client's project URL shows not found.

## Security notes

- All portal pages require sign-in.
- Project pages are scoped to the signed-in freelancer or assigned client; unauthorized IDs return 404.
- Only the assigned client can submit feedback, and only for a milestone belonging to the project.
- Django manages passwords. Never commit `.env` or production credentials.
- Use fictional data. This public demo is not intended for real invoices or confidential deliverables.
